# Chrome Web Store release 3.0.7

The publisher dashboard and public listing showed version 3.0.6 on 22 October
2026. This release updates the existing item
`nhlnehondigmgckngjomcpcefcdplmgc`; it does not create another extension.

## Release scope

Existing local wallets show the security upgrade popup and remain in recovery
mode. Users can export backups, transfer assets out, unstake, redeem unlocked
funds and use supported DeFi withdrawal and claim actions. Deposits, swaps, new
staking and arbitrary dApp signing remain blocked on those wallets. New normal
use requires a fresh root generated by the updated wallet. Re-importing an old
seed or editing metadata cannot bypass recovery mode.

The release must preserve the wallet storage and password protections shipped
in 3.0.6 (source `a1dafd8f85fa5bc08e8792f8cb295dbcc1a105ef`). Wallet
records encrypted by that version must remain readable after the update.

Bitcoin mainnet/testnet address discovery, balances and transaction history are
available. SORA Nexus Taira testnet accounts, balances, transaction history and
IrohaConnect dApp connections are available. Bitcoin and Iroha sends remain disabled.
Nexus mainnet remains disabled by default. Production builds disable test-only
and smoke flags. No customer secrets or build credentials are committed.

## Store release note

Security update: existing wallets now display upgrade guidance and are limited
to recovery actions. Create a new wallet in the updated extension, back it up,
then move your assets to its new addresses. You can still export backups, send
funds out, unstake, redeem, and withdraw supported DeFi positions from old
wallets. Deposits, swaps and other normal use require a new wallet.

## Store feature description

Bitcoin: manage Bitcoin mainnet and testnet addresses, discover existing address
activity, and view balances and transaction history. Bitcoin sending is not
available in this release.

SORA Nexus Taira testnet: access testnet accounts, balances and transaction
history, with IrohaConnect dApp pairing and per-request signature approval for
eligible new wallets. Taira asset transfers are not available in this release.
SORA Nexus mainnet is disabled by default.

## Validation and publication

Use Node 24.19.0 and Yarn 4.17.0 in a clean release checkout, then run:

```sh
yarn env-cmd -f .env.chrome-release.local -- yarn prepare:chrome-release
```

The gate includes unit/type/lint checks, browser smoke, security scanners,
production identity/configuration checks and two byte-identical package builds.
Record the source commit and ZIP SHA-256 from
`dist/extension/chrome-release-provenance.json` with the upload evidence.

The configuration importer remains pinned to the reviewed 3.0.5 reference CRX;
that reference is separate from the minimum store-version check, now 3.0.6.
The version gate rejects an upload that would reuse the published version.

Use the existing store listing, keep its extension ID, review the final
permissions and privacy declarations, upload the exact validated ZIP and submit
for review with publication after approval. Submission is not proof that the
update is live. Preserve the published 3.0.6 package and its recorded hash for
comparison; any rollback package also needs a higher Chrome version.

## Firefox regression review

The production Firefox build retains 41 reviewed lint warnings (40
`DANGEROUS_EVAL`, one `UNSAFE_VAR_ASSIGNMENT`), with no errors or notices.
The six warning-bearing background vendor files match the prior baseline
byte-for-byte. The three changed application chunks retain the same 19 flagged
syntax sites after minifier identifier renaming: dependency global-object
fallbacks, legacy bind/generator detection, intrinsic `eval` references, and
Vue's compiled static-content insertion. No new evaluation sites were added.
The baseline records the new exact positions and file hashes. The runtime
smoke still verifies that CSP rejects dynamic `Function` execution.

CI obtains the pinned Firefox runtime from Mozilla with checksum verification
because the repository's action policy rejects the previous third-party setup
action. The version pin, runtime assertions and permissions are unchanged.
