# Browser platform ownership

This repository owns the browser extension, its TypeScript protocol implementations, its remote configuration, and retained release tooling and backup services. Changes to the extension and the modules it uses are reviewed together. The existing SORA dependency-removal audit prevents reintroducing the retired shared SDK packages.

`remote-config/production` and `remote-config/development` contain independently maintained chain catalogs, features, fiat data, onboarding assets, and scam lists. All nested legacy host URLs are rehosted in this repository; `config/remote-config-imports.json` records source commits, import hashes, case normalization, and explicit fixes for unavailable artwork. Run `python3 scripts/test-remote-config.py` and `python3 scripts/verify-remote-config.py` to verify the data and exact filename case before publishing.

The public website belongs to `soramitsu/fearless-site-web`, the fourth retained repository. Its own CI verifies dependencies, app associations, generated network data, types, and the production build. Keep its existing hosting project connected to that repository. Useful changes from the former browser `site/` copy have been reconciled with the newer standalone website; the duplicate source and browser website workflow are removed.

The native applications belong to `soramitsu/fearless-iOS` and `soramitsu/fearless-Android`. Their native modules and runtime data are owned and tested within those respective repositories. Import provenance is historical evidence, not a build dependency on the retired source repositories. Legacy raw configuration URLs used by older installed applications cannot be redirected by moving files; repository retirement must account for those consumers separately.

`tools/release-readiness/` owns the backup challenge and owner-authority service sources, their lockfiles, and the retained release tooling. The passkey-services workflow tests both implementations and their contracts. Service publication, production configuration and deployment attestations still require their explicit release gates; source consolidation does not deploy or enable a service. Historical multi-repository audit workflows are kept inside that directory for evidence compatibility and are not active workflows in this repository.
